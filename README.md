## 9주차: 서비스 제보 폼

목록 위 `+` 버튼에서 서비스를 제보하거나 정보를 수정할 수 있게 했습니다. 수정을 누르면 기존 이름 칸이 나오고, 추가로 바꾸면 숨겨지면서 입력도 막힙니다. 제보 내용은 브라우저에만 저장됩니다.

이름은 2~80자, 내용은 10~500자이고 앞뒤 공백은 뺍니다. 주소는 500자 이내의 HTTP/HTTPS만 받으며, 아이디나 비밀번호가 들어간 주소는 막았습니다. 글자 수와 입력 상태를 보여주고, 저장 중에는 버튼을 누를 수 없게 했습니다.

### 확인한 내용

1. 빈칸이나 잘못된 주소로 저장해보고, 내용을 고쳤을 때 오류가 없어지는지 확인했습니다.
2. 추가와 수정을 바꿔 기존 이름 칸이 나오고 숨겨지는지 확인했습니다.
3. 저장한 뒤 다시 작성을 눌러 처음 상태로 돌아오는지 확인했습니다.

PC와 모바일에서 확인했고 영어 화면도 같이 봤습니다. 저장 공간을 가득 채웠을 때도 입력은 남아 있었고, 공간을 비우고 다시 시도하니 저장됐습니다.

## 10주차: 메뉴와 서비스 탐색

링크 만들기는 주소 입력, 서비스 찾기는 비교 목록, 이용 안내는 선택 기준으로 연결했습니다. 메뉴도 기존 링클 버튼의 테두리와 그림자에 맞췄고, 아이콘과 밑줄로 현재 위치를 표시했습니다.

목록은 용도별 카테고리와 검색어, 가입·요금·광고 조건을 함께 적용합니다. 모바일에서는 메뉴를 펼쳐 이동하고 목적지를 고르면 닫힙니다.

### 확인한 내용

- 이용 안내에서 새로고침한 뒤 뒤로 가니 서비스 찾기와 현재 메뉴 표시가 함께 돌아왔습니다.
- 개발자용을 선택하고 `zz-no-match-uiux-101`을 검색했습니다. 전체 344개 → 개발자용 124개 → 검색 결과 0개로 바뀌었고, 조건 초기화 후 344개가 돌아왔습니다.
- 390px 화면에서 메뉴를 열고 닫거나 목적지를 선택했을 때 버튼 문구와 `aria-expanded`가 맞게 바뀌었습니다. Esc로도 닫혔습니다.
- 밝은 화면과 어두운 화면, 영어 메뉴에서 아이콘과 메뉴 이름을 확인했습니다.

### 배포 페이지에서 확인한 단축 흐름

2026년 11월 14일, 10주차 GitHub Pages 배포 후 Chrome에서 다시 확인했습니다. 설정은 만료 기간 없음, 사용 횟수 제한 없음입니다.

| 조건과 실행 순서 | 확인 결과 |
| --- | --- |
| `https://example.com` 입력 → 링크 확인 → 단축하기 | 실제 단축 주소 `https://llnk.kr/ae74p3`와 복사 완료 안내가 나왔습니다. |
| 생성된 링클 주소를 다시 입력 → 링크 확인 → 단축하기 | 서버가 요청을 거절하고 ‘이미 LlNK.kr로 단축된 링크는 다시 단축할 수 없습니다.’가 표시됐습니다. 결과 링크는 나타나지 않았습니다. |
| `ftp://example.com` 입력 → 링크 확인 | HTTP/HTTPS만 지원한다는 안내가 나오고 단축 요청을 막았습니다. |
| 성공 또는 실패 후 다시 시작 | 입력·결과·안내가 지워지고 주소 입력란으로 초점이 돌아왔습니다. |

새로 테스트할 때는 첫 단계에서 생성된 주소를 두 번째 단계에 넣으면 됩니다. 입력 오류와 서버의 요청 거절을 각각 확인했으며, 통신 장애나 HTTP 503을 실제 배포에서 확인한 것은 아닙니다.

배포 페이지에서 PC와 390px 모바일 화면을 확인했습니다. 메뉴 이동·새로고침·뒤로 가기, 필터 초기화, 모바일 메뉴 열기·선택 후 닫기·Esc, 기존 상세 화면과 제보 폼 전환도 정상 동작했습니다. 모바일에서도 실제 링크 생성과 다시 시작을 확인했습니다.
